# Migration note: RFC 9457 error responses (2026-11-24)

**What changed.** Every error from `/api/v1/*` is now an RFC 9457 problem document, sent as `application/problem+json`. The old envelope is gone.

| Before | After |
|---|---|
| `{ "error": { "code": "NOT_FOUND", "message": "…", "details": [...] } }` | `{ "type": "urn:problem-type:muzikhub:not-found", "title": "Not Found", "status": 404, "detail": "…", "code": "NOT_FOUND", "instance": "/api/v1/…", "errors": [...] }` |
| `body.error.code` | `body.code` (unchanged values) |
| `body.error.message` | `body.detail` |
| `body.error.details` | `body.errors` (same `{ path, message }` items) |

- `type` is a stable URN per code. It identifies the problem type and is not a web page.
- `title` is the HTTP status phrase.
- `instance` is the request path, including the query string.

**Not changed.**
- HTTP status codes and the `code` values themselves.
- Success responses.
- Better Auth endpoints (`/api/auth/*`), which keep the library's own error format; the web app handles them with the auth client.

**Client code.** The web app's single adapter (`apps/web/src/lib/api.ts`, `request()`) was updated in the same commit and still throws `ApiRequestError(status, code, message, details)`, so UI code needs no changes. Any other client should read `code`, `detail` and `errors`. The schema is `problemSchema` in `@muzikhub/shared`.
